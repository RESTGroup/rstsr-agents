# RSTSR Project

RSTSR: an n-dimensional rust tensor toolkit (common name), REST rust-based electronic structure toolkit subproject for tensor support (formal name).

## Ecosystem map

This file is shared across the rstsr repositories by symlink to the `rstsr-agents` repository (setup: see `README.md` of `rstsr-agents`). Depending on the checkout you are working in:

- `rstsr` - the core workspace: `rstsr-core` (tensor types, storage, device traits, naive and faer reference devices), `rstsr-common` (errors, dimension types), `rstsr-dtype-traits`, `rstsr-blas-traits`, `rstsr-linalg-traits`, `rstsr-sci-traits`, `rstsr-native-impl` (rayon reference impl), `crates-device/` (OpenBLAS, MKL, BLIS, AOCL, KML backends), `crates-plugin/rstsr-tblis` (einsum plugin).
- `rstsr-ffi` (sibling repo) - FFI bindings to C BLAS/LAPACK libraries (`rstsr-openblas-ffi`, `rstsr-mkl-ffi`, `rstsr-lapack-ffi`, ...).
- `rstsr-book` (sibling repo) - documentation project; developer docs and ADRs under `rstsr-book/dev/` (online: https://restgroup.github.io/rstsr-book/).
- `rstsr-agents` (sibling repo) - this repository: shared agent instructions, skills, and rules.

Reference checkouts (NumPy/SciPy/array-api clones used by the test skills) live at a per-developer location, not a fixed one: record yours in `AGENTS.local.md` (e.g. `Reference checkouts: /path/to/dir`); if a skill needs one and it is neither recorded nor resolvable, ask the user. `../other-repos/` is only the maintainer's example. Other cross-repo paths (e.g. `../rstsr-book/`) assume the standard pack layout (all repos siblings in one folder); in a standalone checkout, adjust accordingly.

## Important notices to AI code agent

- This file (`AGENTS.md` / `CLAUDE.md`) is always read first. If `AGENTS.local.md` exists at the current repository root, read it as well: it supplements this file, and where explicitly stated, overrides it. It is per-developer and gitignored.
- When writing or reviewing rstsr-core (and trait/device crate) internals, read `rules/code-concepts.md` of this repository first.
- Please follow skill `git-commit-coauthor` when git commit or opening PRs. Code agent is not supposed to automatically commit codes, even given enough permissions (unless user explicitly instructs in session).
- If some large part of code is generated by AI (a whole file or module, or large part of a file), it is recommended to add message like `Most or all contents generated by AI (model [glm-5.2/deepseek-v4-pro/chatgpt-5.6-sol/...])`. Note the model is not related to code agent (Claude/Codex can still use models other than claude/chatgpt, the code agent should double check the model used for code generation).
- The user may interact in any language (Chinese, English, for example). As AI agent, communicate in the same language as the user. However, code, code comments, documentation, and commit messages should always be in English.

## Developer resources

- **Setup** (new checkout or broken/dangling links): skill `agent-setup` bootstraps the `.claude` / `.agents` / `CLAUDE.md` / `AGENTS.md` symlinks - run `skills/agent-setup/scripts/link.sh` of this repository (auto-detects the sibling checkout; see its SKILL.md and this repository's README.md).
- **Skills** (operational how-to): see `skills/` of this repository, reached from any repo through your `.claude` (Claude Code) or `.agents` symlink - notably `cargo-inst` (build/test commands), `test-conventions` + `core-test` (rstsr-core test authoring), `git-commit-coauthor` (commit and PR conventions).
- **Rules** (reference material): `rules/code-concepts.md` - core types and naming conventions.
- **Dev docs & ADRs** (design rationale, the "why"): `rstsr-book/dev/` (online: https://restgroup.github.io/rstsr-book/) - e.g. ADR-0002 (entry-binary test matrix).

## Notices to human developers

This project is currently not fully-driven by AI. At current time (2026/08), we notice the strong potential of AI, but we feel this is not fully proven for maintaining such kind of project. We will
- allow full AI usage (weak or no manual review) in testing, FFI binding or C-code translation.
- allow partial AI usage (with manual review) otherwise; we do not seek 100% human involvement, use AI for real but not against AI or treat AI as god.

For setup (symlinks, standalone checkouts, local configuration), see `README.md` of this repository.
