# rstsr-aocl-ffi (AMD Optimizing CPU Libraries)

Upstream: [AMD Optimizing CPU Libraries](https://www.amd.com/en/developer/aocl.html)
(AOCL). Sources live under the GitHub `amd` organization, but the tracked
upstream is the **release install tree**: the headers this crate binds
(`blis.h`, `FLAME.h`) are generated by AOCL's own build, so only the shipped
copies are authoritative. The crate generates two modules, `blis` (from
`blis.h`) and `flame` (from `FLAME.h`); `lapack` and `lapacke` are **not**
generated here - their source files are symlinks into `rstsr-lapack-ffi`, and
the local `mod.rs` only re-points dynamic loading at `libflame`.

## Upstream distribution

The upstream "checkout" is the install tree, and where it sits is
per-developer: read it from the repo-root `AGENTS.local.md` /
`CLAUDE.local.md` (a `Resources and Directories` entry; if none records one,
ask). The non-root default layout, used as the example below, is
`$HOME/aocl/<version>/gcc/{MT,ST}`.

Get `aocl-linux-gcc-<version>.tar.gz` from the AOCL download page (EULA
click-through), keep it wherever you keep downloads, verify the SHA-256
published on the download page, unpack, then:

```bash
cd <download dir>/aocl-linux-gcc-<version>
./install.sh          # default root $HOME/aocl -> <root>/<version>/gcc/{MT,ST}
# options: -t <dir> custom install root, -l <libs> subset, -i lp64|ilp64
```

`./install.sh` always lays down both the `ST` (single-threaded) and `MT`
trees, whether in the default root or under `-t`. Record the verified tarball
and the resulting install tree in `CLAUDE.local.md` - later runs read the
location from there, not from this reference.

The version to record is the release (`5.3.0` as of 2026-10); it is echoed by
`FLA_LIBFLAME_VERSION` in `FLAME.h`, by the top-level tarball name, and at
runtime by `bli_info_get_version_str()` ("AOCL-BLAS 5.3.0 Build 20260507").

Layout of each tree: per-component dirs (`amd-blis`, `amd-libflame`, ...) plus
merged `include_LP64`/`include_ILP64` and `lib_LP64`/`lib_ILP64`. MT vs ST
differ in `blis.h`, `cblas.h`, `FLAME.h`, `aocl_dlp_config.h`; LP64 vs ILP64
differ in `blis.h`, `cblas.h`, `FLAME.h` (the `typedef ... integer` targets).
The crate vendors the **MT + LP64** variants: bindings are LP64-shaped and the
`ilp64` cargo feature cfg-switches the Rust aliases.

## Vendored headers

`header/` is the binding input: the top-level C headers copied from
`MT/include_LP64` (blis.h, FLAME.h, cblas/lapack/lapacke, plus other
components' headers kept for provenance). Refresh every already-vendored file
from the new install and byte-verify; delete files upstream dropped. Only
`blis.h` and `FLAME.h` feed the generators - the rest do not affect output.

`header/omp.h` is **not** from AOCL: it is the system GCC's libgomp `omp.h`,
vendored because `gen_flame.py` rewrites FLAME.h's live `#include <omp.h>` to
a local include (upstream annotates those includes `// skipped`, but they are
not commented out). Refresh it from the host GCC only if bindgen complains.

## Generator

Two jupytext-style scripts under `rstsr-aocl-ffi/scripts/`, run as plain
Python from that directory (cwd matters - paths come from `os.getcwd()`) with
the Python that carries `tree_sitter` + `tree_sitter_rust` and the `bindgen`
CLI on PATH:

```bash
cd rstsr-aocl-ffi/scripts
python gen_blis.py && python gen_flame.py
```

- `gen_blis.py`: patch `#include <omp.h>` out of `blis.h`, run bindgen, drop
  the `BLIS_INT_TYPE_SIZE` / `BLIS_BLAS_INT_TYPE_SIZE` / `pub type f77_int`
  lines (those Rust aliases come from `blis_types.rs`), regex-strip the
  locally-emitted `CBLAS_*` enums (they come from `rstsr-cblas-base`), split
  with `util_dyload.dyload_main`, copy into `src/blis/`, `cargo fmt`.
- `gen_flame.py`: rewrite the omp include to the local file, run bindgen,
  remove the generated `integer`/`uinteger` aliases (**regex + assert** - an
  exact-string patch silently stopped matching when 5.3 changed the typedef
  target from `int` to `int32_t`, leaving a local `i32` alias that shadows the
  ILP64-aware one), prepend `pub(crate) use crate::blis_types::*;`, split,
  copy into `src/flame/`, `cargo fmt`.
- `src/blis/mod.rs`, `src/flame/mod.rs` are hand-written and never
  overwritten. `src/lapack/` and `src/lapacke/` are symlinks into
  `rstsr-lapack-ffi`; their version follows that crate (netlib LAPACK), not
  AOCL - a provenance skew that is accepted, like OpenBLAS's.

Patches whose target is a generated declaration are the sharp edge here (see
the `integer` case above): they must fail loud, and the diff must be reviewed
for a patch that silently stopped matching - a silent miss still compiles.

## Verification

```bash
cd rstsr-ffi
cargo check -p rstsr-aocl-ffi --no-default-features
for f in blis flame lapack lapacke; do
    cargo check -p rstsr-aocl-ffi --no-default-features --features "$f"
done
cargo check -p rstsr-aocl-ffi                                     # default: blis, lapack
cargo check -p rstsr-aocl-ffi --features dynamic_loading
cargo check -p rstsr-aocl-ffi --features ilp64                    # and lp64_as_int
cargo check -p rstsr-aocl-ffi --no-default-features --features "blis,flame,lapack,lapacke,dynamic_loading,ilp64"
cargo clippy -p rstsr-aocl-ffi --all-targets --all-features -- -D warnings
cargo fmt --all -- --check
```

- **Coverage audit** (the crate has no checker script): every function in
  `src/blis/ffi_extern.rs` / `src/flame/ffi_extern.rs` should be an exported
  symbol of `libblis-mt.so` / `libflame.so`. Baseline misses are expected -
  `bli_*` internals declared but not exported (~2k), the `lpgemm_*` family
  (implemented in `libaocl-dlp`), and a few hundred libflame internals
  (`AOCL_FAL_*`, `FLASH_*`, `FLA_Apply_*`). What matters is the **delta**
  against the previous run: it must be explainable by the upstream change.

  ```bash
  # <install root> = the tree recorded in CLAUDE.local.md, e.g. ~/aocl/5.3.0
  grep -oE 'fn [a-zA-Z0-9_]+\(' rstsr-aocl-ffi/src/blis/ffi_extern.rs \
      | sed 's/fn //;s/($//' | LC_ALL=C sort -u > /tmp/blis_names.txt
  nm -D --defined-only <install root>/gcc/MT/lib_LP64/libblis-mt.so \
      | awk '{print $NF}' | LC_ALL=C sort -u > /tmp/blis_exports.txt
  LC_ALL=C comm -23 /tmp/blis_names.txt /tmp/blis_exports.txt
  ```

  Keep `LC_ALL=C` on every sort that feeds `comm`: with locale `sort` the
  comparison reports phantom removals (it once "removed" 975 functions that
  were simply reordered).
- Runtime smoke: a scratch example (`--features "flame,lapacke,dynamic_loading"`)
  that prints `bli_info_get_version_str()`, runs a `cblas_dgemm` and a
  `LAPACKE_dsyevd`, executed with `RSTSR_DYLOAD_AOCL_BLIS` /
  `RSTSR_DYLOAD_AOCL_FLAME` pointed at `libblis-mt.so` / `libflame.so` in the
  install tree's `MT/lib_LP64` (paths from `CLAUDE.local.md`). `libflame`
  finds `libblis-mt` via its own rpath and links the system `libgomp`, so
  there is no OpenMP preload dance (unlike MKL). Delete the example afterwards.

## Pitfalls

- **Variant selection**: vendor MT/LP64. The ST tree flips
  `BLIS_ENABLE_OPENMP` / `FLA_MULTITHREADING_MODEL` in the output; the ILP64
  tree changes the `integer` typedefs that `blis_types.rs` is supposed to own.
- **Stale vendored headers are silent**: the generator reads only `header/`.
- **The bindings embed system-header types**: `blis.h`/`FLAME.h` reference
  `FILE`, `pthread_*`, so `ffi_base.rs` carries glibc structs (`_IO_FILE`,
  `__pthread_mutex_s`, ...). Regenerating on a different distro/glibc yields
  environment hunks - classify them as environment, not upstream.
- **bindgen version artifacts**: 0.73.2 emits `__BindgenBitfieldUnit` for
  those glibc bitfields and drops `Copy`/`Clone` on some opaque structs; it
  trips `clippy::manual_div_ceil` / `clippy::ptr_offset_with_cast`, allowed at
  crate level in `src/lib.rs` alongside the pre-existing generated-code allows.
- **Do not chase the unresolved `lpgemm_*` entries** by loading
  `libaocl-dlp` from the crate; loading auxiliary runtimes is the
  application's decision (same reasoning as MKL's OpenMP).
- **Version policy**: patch by default; here 0.2.1 -> 0.3.0 because 5.3 widens
  `FLA_Error`/`FLA_Dimension` and removes ~255 `bli_*` functions. Update the
  crate readme's version line + changelog, `Cargo.toml`, and the root
  `readme.md` table row.
